# Comment Tree Exporter for YouTube — Chrome

Независимое расширение Manifest V3 для локальной выгрузки доступных публичных комментариев и ответов YouTube. Сервер, API-ключ и установка npm-зависимостей не требуются.

> Это неофициальный инструмент. Он не создан, не одобрен и не поддерживается YouTube или Google.

## Возможности версии 1.3.0

- интерфейс на русском и английском языках;
- режим языка **Авто** по языку Chrome, а также ручной выбор **Русский / English**;
- синхронная локализация интерфейса, ошибок, служебных сообщений YouTube и TXT-файла;
- древовидный предпросмотр комментариев и ответов прямо в расширении;
- прямая кнопка перехода к каждому комментарию на YouTube;
- цветные уровни ответов и подпись, кто кому ответил;
- необязательный вход через Google OAuth и показ авторизованного YouTube-канала;
- публикация ответа из карточки через официальный YouTube Data API после явного нажатия пользователя;
- сохранение опубликованного ответа в локальную базу для экспорта;
- библиотека отдельных наборов по видео и восстановление без повторного сетевого сбора;
- автосохранение черновиков по видео, адресату и каналу;
- история отправки и сохранение неопределённого результата между перезагрузками;
- экспорт JSON, JSONL, CSV и читаемого TXT с иерархией;
- светлая и тёмная темы;
- пауза, остановка, лимит и регулируемая задержка;
- порционный предпросмотр по 300 записей для экономии памяти;
- курсорный экспорт JSON/JSONL/CSV напрямую из IndexedDB;
- ручное удаление локально сохранённых комментариев;
- встроенная двуязычная страница конфиденциальности.

## Установка из ZIP или папки

1. Распакуйте архив в постоянную папку. Не удаляйте её после установки.
2. Откройте `chrome://extensions`.
3. Включите **Режим разработчика / Developer mode**.
4. Нажмите **Загрузить распакованное расширение / Load unpacked**.
5. Выберите папку, в корне которой находится `manifest.json`.
6. Откройте публичное видео YouTube и нажмите эмблему расширения.

После обновления файлов нажмите кнопку перезагрузки на карточке расширения. Расширение умеет само подключить content script к уже открытой вкладке YouTube; ручное обновление страницы обычно не требуется.

## Google-вход и ответы

Пользователь подтвердил Google-вход и реальную публикацию ответа в версии 1.2.0. Версия 1.3.0 добавляет хранение и черновики; её миграция проверена на тестовой базе в Chrome, а обновление пользовательской установки ещё предстоит проверить. Сбор и экспорт остаются доступны без входа.

1. Для существующей установки обновите файлы в той же папке и перезагрузите расширение на `chrome://extensions`. Дополнительное разрешение `identity` используется для Google-входа.
2. Нажмите **Войти через Google** на основной странице и проверьте отображаемые название и ID YouTube-канала.
3. Дождитесь завершения или остановите выгрузку, затем нажмите **Ответить** в карточке. Отправка доступна только при определённом корневом комментарии ветки.
4. Перед отправкой проверьте адресата, текст и канал в редакторе. Подтверждённый API ответ сохраняется локально и включается в последующий экспорт.

Публичный OAuth Client ID находится в `manifest.json`; API-ключ для отправки не требуется. В Google Cloud этот клиент должен иметь тип **Chrome Extension** и быть привязан к ID именно установленного расширения. Текущий ID показан в блоке **Проблемы со входом?**. Из распакованной папки по другому пути Chrome может получить другой ID: перед распространением нужно зафиксировать постоянный ID через публичный ключ расширения и соответствующую OAuth-настройку.

В проекте OAuth-клиента должны быть включены YouTube Data API v3 и scope `youtube.force-ssl`; для Testing аккаунт должен быть добавлен в тестовые пользователи. Создание Client ID не подтверждает корректность этих настроек. Для публичного выпуска отдельно проверяются требования OAuth verification.

Кнопка **Отключить** очищает кешированную авторизацию этого расширения. Отозвать разрешение у Google можно по ссылке в блоке помощи. Токены не записываются в базу комментариев или файлы экспорта. При сетевом обрыве результат публикации может быть неизвестен: сначала проверьте ветку на YouTube. POST автоматически не повторяется и внутренний endpoint не используется как запасной способ публикации.

MCP и фоновый мониторинг в эту версию не входят. План: `../../OAUTH_MCP_SPEC.md`.

## Локальные данные

Комментарии сохраняются в IndexedDB только на устройстве пользователя, отдельно по video ID. Повторная выгрузка объединяет записи по ID; ранее сохранённые записи не удаляются только из-за отсутствия в новой выборке. Поэтому библиотека представляет накопленный набор, а не гарантированно актуальный список всех доступных на YouTube записей.

Ссылка **Сохранённые видео / Saved videos** в popup открывает библиотеку без ввода URL. Блок с тем же названием на основной странице открывает выбранный набор без сетевого сбора. При открытии основной страницы восстанавливается последний обновлённый набор. Перезагрузка не запускает парсер; новый сбор выполняется кнопкой **Собрать / обновить**. Кнопка **Удалить это видео / Delete this video** удаляет только выбранный набор вместе с его черновиками и историей отправки после подтверждения. Другие видео и скачанные файлы не затрагиваются.

Черновики сохраняются при вводе по video ID, ID адресата и ID авторизованного канала. Закрытие редактора сохраняет черновик; очистка текста удаляет обычный черновик. При неизвестном результате публикации его состояние сохраняется после перезагрузки. Проверьте ветку на YouTube; разрешить повтор можно отдельной кнопкой только после проверки, что ответ не появился. Положительный API-ответ, история отправки и удаление черновика сохраняются одной транзакцией.

При первом обновлении закройте старые страницы расширения и перезагрузите его в прежней папке: открытые страницы старой версии могут блокировать обновление IndexedDB. Таблица версии 1.2 не содержит ID видео и остаётся исходной резервной копией. При наличии старых данных укажите соответствующую ссылку и нажмите **Привязать прежние данные к ссылке**. Не назначайте случайное видео: от этого зависят правильность ссылок и адресатов. Повторный импорт не создаёт дубликаты ID. Смена ID расширения или удаление расширения может лишить доступа к прежнему хранилищу; перед обновлением важные данные стоит экспортировать.

Настройки языка, темы, экспорта, признак восстановления входа и факт привязки старого набора находятся в `chrome.storage.local`. Сбор, публикация, импорт и удаление одного видео защищены от одновременной записи из нескольких вкладок. Для просмотра изменений из другой вкладки нажмите **Открыть локальные данные**.

Подробности: [PRIVACY.md](PRIVACY.md).

## Проверки разработчика

```powershell
cd extension\Chrome
npm.cmd test
npm.cmd run check
npm.cmd run build:release
```

Готовый архив создаётся в `release/Comment-Tree-Exporter-for-YouTube-Chrome-v1.3.0.zip`. В нём нет исходного JSON OAuth, API-ключа, тестов, npm-файлов, упаковочных скриптов и большого мастер-изображения.

Браузерная проверка с подставными Chrome Identity и API, без обращений к реальному аккаунту: `npm.cmd run test:browser`. Нужен Playwright в окружении разработки; путь к его entrypoint можно передать через `PLAYWRIGHT_MODULE_PATH`, к Chrome — через `CHROME_PATH`. Производственных npm-зависимостей нет.

## Ограничения

Сбор комментариев использует неофициальный внутренний интерфейс YouTube. Для этого сбора нет суточной квоты YouTube Data API, однако возможны временные ограничения, HTTP 403 и несовместимость после изменений YouTube. Получаются только записи, доступные текущему браузеру; удалённые и скрытые модерацией комментарии недоступны.

Сбор выполняется через вкладку YouTube. Если подходящей вкладки нет, расширение создаёт временную фоновую вкладку и закрывает её после завершения. Ответы отправляются отдельно через официальный API с Google OAuth; активная браузерная сессия YouTube для отправки не используется. На дату версии одна публикация стоит 50 единиц квоты проекта. Полной безлимитности нет. Одновременно поддерживается один канал, однозначно возвращённый API; несколько каналов/Brand Account требуют отдельной живой проверки.

Иерархический TXT требует построения дерева в памяти. JSON, JSONL и CSV оптимизированы для больших наборов и создаются курсором из локальной базы.
